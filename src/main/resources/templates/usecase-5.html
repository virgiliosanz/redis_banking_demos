UC5

Transaction Deduplication

Duplicate Payment Prevention — avoid double-charging on bank transfers using Redis SET with NX + EX flags.

How it works
  1. An application attempts to write data to a database.
  2. Deduplication check via hash stored in a Redis Set or probabilistic data type:
    a. If data does not exist in Redis → allow the write to the database.
    b. If data already exists → deny (duplicate detected).

Code Showcase

// SETNX pattern — atomic check-and-set with TTL
// Key convention used by DeduplicationService: "uc5:{txHash}"

String txHash = sha256Short(sender + receiver + amount + windowId);
String key = "uc5:" + txHash;

// SET key value NX EX 300 — atomic "set if not exists" with 5-min TTL
Boolean wasSet = redis.opsForValue()
    .setIfAbsent(key, "1", Duration.ofSeconds(300));

if (Boolean.TRUE.equals(wasSet)) {
    // First time within the window — process the payment
    return "ACCEPTED";
} else {
    // Key already exists — duplicate detected
    return "DUPLICATE";
}
# First attempt — key created, payment accepted
SET uc5:a1b2c3d4 "1" NX EX 300
# → OK

# Second attempt (within 5 min) — blocked
SET uc5:a1b2c3d4 "1" NX EX 300
# → (nil)   ← duplicate detected

# Check remaining TTL
TTL uc5:a1b2c3d4
# → (integer) 287

# After TTL expires, the same tx is accepted again
SET uc5:a1b2c3d4 "1" NX EX 300
# → OK
# ═══ Bloom filter alternative ═══
# ⚠ Conceptual alternative — NOT implemented in this demo.
#   The live demo uses the SET NX EX pattern above. A Bloom filter
#   (RedisBloom module) trades a tiny false-positive rate for a
#   large memory saving at very high volumes (millions of tx/day).

# Create filter (1M capacity, 0.01% error rate)
BF.RESERVE uc5:bloom:2024-01-15-14 0.0001 1000000

# Check + add in one step
BF.ADD uc5:bloom:2024-01-15-14 "a1b2c3d4e5f6"
# → (integer) 1  ← new item, not seen before

BF.ADD uc5:bloom:2024-01-15-14 "a1b2c3d4e5f6"
# → (integer) 0  ← already exists = DUPLICATE

# Check without adding
BF.EXISTS uc5:bloom:2024-01-15-14 "a1b2c3d4e5f6"
# → (integer) 1  ← exists
// Java equivalent with Spring Data Redis (Lettuce)
// Bloom filters don't support per-item TTL — use a
// time-bucketed filter name, e.g. "uc5:bloom:2024-01-15-14".

String filter = "uc5:bloom:" + hourBucket;

// BF.ADD via RedisCallback — conn.execute runs any Redis command
Long added = (Long) redis.execute((RedisCallback<Object>) conn ->
    conn.execute("BF.ADD",
        filter.getBytes(StandardCharsets.UTF_8),
        txHash.getBytes(StandardCharsets.UTF_8))
);

if (added != null && added == 1L) {
    return "ACCEPTED";   // new transaction
} else {
    return "DUPLICATE";  // already seen
}
